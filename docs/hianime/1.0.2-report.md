## 1. Executive Summary

Connector version **`1.0.2`** has been prepared and published to [`Testing-Modules-AR`](https://github.com/kas021/Testing-Modules-AR) to leverage the native playback header improvements introduced in **Aroki 2.0.4** (commit `e5562db`) and the visual loading state improvements in **Aroki 2.0.5** (commit `76044a5`).

### Key Operational Takeaways
1. **Minimum App Version Bump to `2.0.4`**:  
   Aroki 2.0.4 introduced native mapping of declared `User-Agent` headers to Apple's dedicated `AVURLAssetHTTPUserAgentKey`. Because GoogleVideo playback cryptographically requires this exact User-Agent, candidate 1.0.2 raises `minimumAppVersion` from `2.0.3` to `2.0.4`.
2. **Empirical GoogleVideo Verification**:  
   We performed fresh HTTP range probes, redirect tracing, and header variations against live GoogleVideo streams extracted from `hianimetv.su`. The tests conclusively demonstrate that:
   - Fresh stream URLs have a long-lived TTL of **8.00 hours** (`28,800 seconds`).
   - Google's `gvs 1.0` server validates the `eaua` parameter strictly against the incoming `User-Agent`. When the declared Windows Chrome User-Agent is passed, GoogleVideo returns **HTTP 206 Partial Content (76 MB MP4)**. When replaced by Apple's `AppleCoreMedia` agent, empty agent, or mobile Safari agent, GoogleVideo returns **HTTP 403 Forbidden**.
   - GoogleVideo does **not** validate the `Referer` header; requests succeed identically with or without Referer.
3. **Current Live Playback Status**:  
   - **CLI Verification**: Successfully verified with `vireo-tool probe-title` on Blogger-backed titles (*Oshi no Ko*, *Jujutsu Kaisen*, *High School! Kimengumi*).
   - **Physical Device Status**: Live playback on the owner's iPhone 15 Pro Max remains **unverified** until the device is updated from build 16 (Aroki 2.0.3) to build 17+ (Aroki 2.0.4 / 2.0.5).
   - **Catalog-Level Provider Limitation**: Titles defaulting to MegaPlay (e.g. *My Melody to Kuromi*) or dead MegaVid embeds (e.g. *100 Meters*) produce 0 stream candidates because MegaPlay requires runtime JavaScript AES decryption and MegaVid returns HTTP 404.

## 2. Technical Investigation of GoogleVideo / Blogger Streams

### 2.1 URL Structure, Parameters & Expiry Analysis

Extracting a fresh stream URL from `[Oshi No Ko] Season 3` Episode 1 yielded:
```text
https://rr1---sn-vgqskndl.googlevideo.com/videoplayback?expire=1788828806&ei=BuyeaqmkB6-9-eUPzNi20Aw&ip=38.154.109.92&id=b148ed354710d3f1&itag=18&source=blogger&requiressl=yes&xpc=Egho7Zf3LnoBAQ==&rms=au,au&susc=bl&svpuc=1&eaua=OfoyTv86HTM&mime=video/mp4&vprv=1&rqh=1&dur=1430.163&lmt=1768526416405748&txp=1311224&sparams=expire,ei,ip,id,itag,source,requiressl,xpc,susc,svpuc,eaua,mime,vprv,rqh,dur,lmt&sig=...
```

* **Timestamp / TTL**:
  - `now`: `1788800006`
  - `expire`: `1788828806`
  - **TTL**: `28,800` seconds (**8.00 hours**). The URLs are not short-lived tokens and remain valid for half a day.
* **Token Parameters**:
  - `eaua`: `OfoyTv86HTM` (Encrypted / Authenticated User-Agent).
  - `sparams`: Declares protected fields: `expire,ei,ip,id,itag,source,requiressl,xpc,susc,svpuc,eaua,mime,vprv,rqh,dur,lmt`.
  - `sig` and `lsig`: HMAC signatures verifying the parameter set.

### 2.2 Empirical Header Matrix & Response Codes

We tested fresh requests against Google's `gvs 1.0` CDN server under controlled header variations:

| Test Case | Request Headers | HTTP Status | Response Payload | Server Assessment |
| :--- | :--- | :--- | :--- | :--- |
| **1. Windows Chrome UA + Referer** | `User-Agent: Mozilla/5.0 (Windows NT 10.0...)`<br>`Referer: https://hianimetv.su/`<br>`Range: bytes=0-1023` | **206 Partial Content** | 1024 bytes (76 MB MP4) | **PASS**: Stream delivered in 379ms. |
| **2. Windows Chrome UA (No Referer)** | `User-Agent: Mozilla/5.0 (Windows NT 10.0...)`<br>`Range: bytes=0-1023` | **206 Partial Content** | 1024 bytes (76 MB MP4) | **PASS**: Referer is not validated. |
| **3. Windows Chrome UA + Blogger Referer**| `User-Agent: Mozilla/5.0 (Windows NT 10.0...)`<br>`Referer: https://www.blogger.com/`<br>`Range: bytes=0-1023` | **206 Partial Content** | 1024 bytes (76 MB MP4) | **PASS**: Any or no Referer accepted. |
| **4. AppleCoreMedia iPhone UA** | `User-Agent: AppleCoreMedia/1.0.0... (iPhone; ...)`<br>`Referer: https://hianimetv.su/`<br>`Range: bytes=0-1023` | **403 Forbidden** | 0 bytes | **FAIL**: Mismatches `eaua` signature. |
| **5. Mobile Safari iOS UA** | `User-Agent: Mozilla/5.0 (iPhone; CPU iPhone OS...)`<br>`Referer: https://hianimetv.su/`<br>`Range: bytes=0-1023` | **403 Forbidden** | 0 bytes | **FAIL**: Mismatches `eaua` signature. |
| **6. Omitted / Empty User-Agent** | `Range: bytes=0-1023` | **403 Forbidden** | 0 bytes | **FAIL**: Mismatches `eaua` signature. |

**Conclusion**: GoogleVideo's HTTP 403 Forbidden is directly and conclusively triggered by User-Agent substitution. Google's server validates that incoming HTTP segment requests carry the exact User-Agent string signed into the `eaua` parameter.

### 2.3 Redirect Tracing
When full GET requests are issued or CDN load-balancing is invoked, GoogleVideo responds with **HTTP 302 Found**, redirecting to regional edge clusters:
```text
Location: https://rr7---sn-jvhh4pcgx-ajtl.googlevideo.com/videoplayback?...
```
- The redirect appends tracking query parameters: `redirect_counter=1`, `cms_redirect=yes`, `ipbypass=yes`, `mip=...`.
- These hostnames are covered by the connector's `"allowedHosts": ["*.googlevideo.com"]` wildcard.

## 3. Interaction with Recent App Improvements

### 3.1 Aroki 2.0.4: Native `AVURLAssetHTTPUserAgentKey` (`e5562db`)
In Aroki 2.0.3 and earlier, custom headers were supplied exclusively through `AVURLAssetHTTPHeaderFieldsKey`. On iOS, Apple's media daemons (`mediaserverd`) override `User-Agent` in that dictionary with `AppleCoreMedia/...`.

In Aroki 2.0.4:
```swift
enum ArokiAssetRequestOptions {
    static func make(headers: [String: String]) -> [String: Any] {
        var remaining: [String: String] = [:]
        var options: [String: Any] = [:]
        for key in headers.keys.sorted() {
            guard let value = headers[key] else { continue }
            if key.caseInsensitiveCompare("User-Agent") == .orderedSame {
                options[AVURLAssetHTTPUserAgentKey] = value
            } else {
                let canonical = key.split(separator: "-").map {
                    $0.prefix(1).uppercased() + $0.dropFirst()
                }.joined(separator: "-")
                remaining[canonical] = value
            }
        }
        if !remaining.isEmpty { options["AVURLAssetHTTPHeaderFieldsKey"] = remaining }
        return options
    }
}
```
Passing `AVURLAssetHTTPUserAgentKey` uses Apple's official API for `AVURLAsset` custom User-Agent propagation. This is designed to preserve the declared Windows Chrome User-Agent and prevent GoogleVideo 403 errors on iOS.

### 3.2 Aroki 2.0.5: Episode Loading Feedback (`76044a5`)
In `DetailView.swift`, `ProgressView() + Text("Loading episodes…")` is now rendered while `appState.seasons(...)` executes. This resolves the user experience issue where the screen appeared to have no episodes during the ~2-second dual-network-fetch period.
